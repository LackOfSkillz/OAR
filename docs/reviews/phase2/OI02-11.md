# OI02-11 Invalidation and execution boundary

Date 2026-11-24. New `Intelligence/NexusCore.lua`, module `Nexus`, **off by default** (setting `on`). It chains state, adapters, graph, score and planner.

- **Re-planning:** on the state events and goal changes, with a trailing debounce (one re-plan per burst, through a module-owned timer). Never in combat: a request made in combat runs after PLAYER_REGEN_ENABLED. No re-planning while paused.
- **Snapshot revisions:** every plan records the state revision it was built on. Any state event moves the revision on, so `IsStale()` reports a plan as outdated after a change (new gear, for example) or after 10 minutes.
- **Player control:** Pin (first step), Skip (left out), Pause, Resume. Saved per character.
- **Execution boundary:** building and evaluating a plan never acts. `Act(stepId)` is the only path; it is meant for the player's click, refuses stale plans, and runs only the producer's own intent (its waypoint function or a Hub page).
- **Lifecycle:** disable cancels the pending re-plan and drops the plan; logout keeps nothing but the player's settings.

`State:Invalidate` now always advances the revision, so a change to a field no one read still makes plans stale.

Tests: `nexus_core_spec` (7):
- off by default;
- no action during planning, action only on Act;
- a burst of events makes one re-plan;
- combat defers the re-plan;
- a gear change makes the plan stale and Act refuses it;
- pin, skip, pause and resume;
- late events after disable or logout do nothing.
