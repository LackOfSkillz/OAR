# OI03-10: Preference and feedback model

**Requirement:** record useful, wrong, ignored and completed separately; a bounded preference adjustment with reset and opt-out; explicit goals stay dominant.

**Acceptance:** ignoring a suggestion doesn't count against it; duplicates can't amplify feedback; every change can be explained and reversed.

## What was built

`Intelligence/Preferences.lua` keeps no vote store. It reads the feedback Outrider already keeps:
- Radar's verdicts, one per suggestion (`char.radarFeedback`)
- What now?'s "Not useful" skips and its shown counts
- outcomes the recorder attributed as "likely" to a plan step you chose

| Vote | From |
|---|---|
| useful | Radar "useful" |
| wrong | Radar "wrong", What now? "Not useful" |
| completed | Radar "done", or a "likely" quest completion after you chose the step (a hint, never proof) |
| neutral | Radar "dismiss" or "snooze": "not now" isn't a judgement |
| ignored | shown and passed over: reported, counts for nothing |

**Rules**
- **No amplification:** one suggestion is one vote; the latest verdict wins, so clicking twice or a repeated completion counts once.
- **The nudge:** per kind of step (quest, gear, gold and so on), (useful + completed − wrong) ÷ (votes + 5), scaled and clamped to ±0.05.
- **Visible:** the nudge is a separate line in the planner's score trace ("your feedback").
- **Goals dominate:** a test shows that the strongest opposite feedback can't flip a goal-driven order.
- **Opt-out:** `prefs.on = false` in the planner's settings means no nudge at all.
- **Reset:** counting starts from now. Earlier votes are ignored, not deleted.
- **Undo:** returns to the previous starting point.
- **Stale plan:** a reset or opt-out changes the planning context, so the current plan goes stale at once.
- **Explain(kind):** gives the counts behind a nudge, for example "1 useful, 0 done, 0 not useful, 0 not now, 1 shown and passed over: +0.017".
