# OI03-02: Outcome event schema

**Requirement:** record bounded, observed events (quest, travel, XP, spending and earning, gear, profession, and permitted death and recovery) and tie them to plan ids when known.

**Acceptance:** events are deduplicated by meaning; missing or secret fields are recorded as unknown; the wrong-character, late-event and unknown-attribution tests pass.

## What was built

**Contract.** A new v4 record, `OutcomeEvent`, is in the shared spec (`docs/contracts/nexus_v4.lua`, so Lua and Python read the same definition). Its fields: eventId, kind, characterKey, sessionId, at, attribution, plus optional subject, amount, context, planId, stepId, late and unknownFields.
- There are 12 kinds: quest_accepted, quest_completed, quest_abandoned, xp_gain, level_up, money_in, money_out, gear_equipped, profession_skill, death, recovery, zone_entered.
- Three new golden fixtures cover a valid record, one with unknown fields, and a rejected kind. Both OTR1 transport files were regenerated; only the two new codes were added.

**Recorder.** `Intelligence/Outcomes.lua` is opt-in (off by default, like the XP recorder) and per character. It keeps the newest 500 records; older ones go to the archive (`outcomeEvents`, added to the preservation audit), never deleted. It listens only to the game's own events, never the combat log:
- QUEST_ACCEPTED, QUEST_TURNED_IN (and the quest's reported XP), QUEST_REMOVED
- PLAYER_LEVEL_UP
- PLAYER_MONEY, with the Ledger's new public `Context()`
- PLAYER_EQUIPMENT_CHANGED
- profession rank increases
- PLAYER_DEAD, PLAYER_UNGHOST and PLAYER_ALIVE
- ZONE_CHANGED_NEW_AREA

**Rules.**
- **Dedup by meaning:** the same kind, subject and amount again within a short window (1 to 10 s, depending on the kind) is one event.
- **Unknown, not guessed:** a missing or secret value is left out and named in `unknownFields`.
- **Only this character:** a record for another characterKey is refused, and so is one dated in the future.
- **Late:** a record from before the play session started, or reported more than 60 s after it happened, is marked `late`.
- **Attribution:** "likely" only when the player pressed Go on a plan step about the same quest, item or map within 30 minutes, and the record isn't late. Otherwise it is "unknown".
  - The click reaches the recorder as `OTR_NEXUS_ACTED`, fired by `NexusCore:Act` and kept in memory only.
  - Nothing is ever "direct": an outcome after a suggestion is not proof that the suggestion caused it.
- **Abandoned:** QUEST_REMOVED also follows a turn-in, so a quest counts as abandoned only if it wasn't turned in just before.
- **Death and recovery:** PLAYER_ALIVE also fires when you release as a ghost, which isn't counted as a recovery.

## Evidence

- `tests/spec/outcomes_spec.lua`, 11 tests:
  - off by default
  - the quest lifecycle (abandoned only without a turn-in)
  - dedup by meaning
  - money in and out with the window context
  - missing and secret values left out and named
  - another character refused; future refused
  - late records marked and never attributed
  - attribution "likely" only for the same thing inside the window, never "direct"
  - death and recovery (a release isn't a recovery)
  - every record is a valid v4 OutcomeEvent tied to the play session
  - the 501st record archives the oldest
- Contract fixtures: Lua, Python and transport tests pass with the new record.
