# OI03-01: Session recorder reconciliation

**Requirement:** extend the existing recorders (SessionXP, Ledger, LootLog, FightMeter, Alts) instead of adding another history; define session boundaries and interruption states.

**Acceptance:** logout, reload, disconnect, multi-character and duplicate-event fixtures show no double counts and no false completed sessions.

## What was there

- **SessionXP:** one record per login. `PLAYER_LOGOUT` fires for a `/reload` too, so a reload saved a record with `final = true`. That was a false completed session, and the next login started another one, so one play session counted as two.
- **Ledger:** the same split. One gold record per logout or reload; the gold-per-hour forecast counted each as a session.
- **LootLog, FightMeter, Alts:** keep no saved per-session history.
  - LootLog's session tally lives in memory.
  - FightMeter reads Blizzard's own meter sessions.
  - Alts counts instance entries per hour.
  - None of them needed a session id. LootLog's in-memory tally restarts after a reload; it is a display only.
- **Data preservation:** `/ride xp60 clear` replaced the saved XP history without archiving it.

## What changed

`Intelligence/PlaySession.lua` is a small shared marker, not a history.

- **Saved:** `char.playSession` holds an id, a segment number, a state and how the last segment ended.
- **At logout:** the session is only marked "closing", because a logout and a reload look the same then.
- **At the next `PLAYER_ENTERING_WORLD`:**
  - `isReloadingUi`: the same session continues, segment + 1, and the last segment ended by "reload".
  - `isInitialLogin` after "closing": the last session ended by "logout".
  - `isInitialLogin` while still "open": no logout was seen, so the last session was "interrupted" (crash or disconnect).
  - Neither flag (zoning): nothing changes.
- **Recorders** stamp their records with `playSessionId` and `segment`. When told how the last segment ended (`OTR_PLAYSESSION`), they set `endReason` on that segment.
  - In SessionXP, a reload segment gets `final = false`: it was not a completed session.
- **Merging:** `PlaySession.Merge` joins segments into play sessions. It sums the totals, takes the first and last values, combines the flags, and returns new tables, so saved records are never changed. Users:
  - `SessionXP:Merged()`
  - `Ledger.Merged()`, which now feeds the gold forecast
  - the companion's `xp_baseline.merge_segments()`, so its XP/hour still counts sessions that included a reload
- **Duplicate events:** the same quest turn-in reported twice within 5 seconds counts once.
- **Archive first:** `/ride xp60 clear` archives the old history (`xpSessionsCleared`, added to the preservation audit) before starting a new one, and clears nothing if archiving fails.
