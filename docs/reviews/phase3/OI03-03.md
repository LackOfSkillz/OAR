# OI03-03: Activity timing

**Requirement:** classify the observable stretches of a session (travel, quest, crafting, dungeon, recovery, unclassified) without pretending to know activity that can't be seen.

**Acceptance:** segments don't overlap or exceed wall time; inactive and unclassified time are reported; no combat log or screenshot source.

## What was built

`Intelligence/ActivityTimeline.lua` is driven by the outcome recorder. It uses the same opt-in switch, and its records are saved in the same store (`char.outcomes.activity`).

**One label at a time**, the first that applies:

| Label | When |
|---|---|
| recovery | dead or a ghost |
| dungeon | `IsInInstance` says party, raid or scenario |
| crafting | a profession window is open |
| travel | `UnitOnTaxi` (on a flight path) |
| quest | a quest event in the last 300 s (accept, turn-in, quest-giver window, objective update, removal) |
| inactive | flagged AFK, or nothing observed for 300 s |
| unclassified | everything else |

**Not guessed:**
- Walking around isn't "travel" and fighting isn't "quest" unless a quest event says so.
- A quiet stretch counts as "inactive" from the last observed moment, not from when the quiet was noticed.

**Segments** are contiguous: each starts where the last ended, so they can't overlap and they always add up to the wall time.
- The detailed list stops at 120 parts per record (`partsCapped`); the totals stay exact.

**Records:** one per play session segment, stamped with the play session id once the login is resolved. The newest 20 are kept; older ones go to the archive (`activitySessions`, in the preservation audit).

**Sources:** game events and state checks only. A test confirms the file contains no combat log or screenshot code.
