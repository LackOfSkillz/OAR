# OI01-06 Code health toolchain

Date 2026-11-24. Status: MOCK_GREEN for the network-free toolchain. **Luacheck and Ruff are not
installed yet:** fetching pinned versions is a network download, which CLAUDE.md rule 10 says to ask
Gary about first. That request is queued for the gate.

## What was added

| Piece | What it does | Where |
|---|---|---|
| `tools/quality.py` | Lua: files over 1500 lines, functions over 150 lines (a tokenizer that skips strings and comments, block matching). Python (companion/, tools/): syntax, unused imports, bare `except`, mutable defaults, `eval`/`exec`. Standard library only. | new |
| Baseline | `docs/quality/baseline.json`: the 23 existing findings, accepted as the starting point | new |
| Gate | `tools/test.ps1` (local and CI) runs `quality.py --selftest` and `--check`; any finding not in the baseline fails the suite | changed |
| Self test | Negative fixtures: a planted 155-line Lua function, keywords hidden in strings, comments and long strings, and a Python file with each banned pattern. All must be caught. | new |
| Lua coverage | `OTR_COVERAGE=<file>` makes `tests/run_tests.lua` record each executed addon line through `debug.sethook`. `quality.py --coverage <file>` writes the report. | changed |
| Report | `docs/quality/report.md`: every finding plus measured line coverage per file | new |

## Measured numbers (2026-11-24, HEAD before this commit `e013761`)

- Findings: 23 (17 Lua functions over 150 lines, 1 Lua file over 1500 lines, 5 Python unused imports).
  The large-function list matches the decomposition targets of OI01-08 to OI01-10: MacroTree,
  Journey, GearShop and Pages-style tab builders.
- Lua line coverage from the full spec run: 33993 of 37473 executable lines (90.7%). "Executable"
  means non-blank, non-comment and not only `end`/`else`/a bracket. Multi-line table constructors
  count once per line, so this is a line measure, not branch coverage. Generated data files are
  excluded.
- Commands: `OTR_COVERAGE=dist/lua_coverage.txt python tools/lua.py tests/run_tests.lua` (1011 passed),
  then `python -I tools/quality.py --coverage dist/lua_coverage.txt`.

## Limits

- The Lua tokenizer is not a full parser. Every finding names file:line for a person to confirm.
- There is no type checker and no complexity metric beyond size yet. Luacheck (unused variables,
  shadowing) and Ruff are the planned upgrade once Gary approves the downloads.

## Acceptance

- Reproducible tools in CI: yes for quality.py (it runs inside test.ps1, which CI runs). Luacheck and
  Ruff are pending the owner's OK.
- No new violations outside the documented baseline: enforced.
- Actual coverage reported, nothing fabricated: 90.7% line coverage, measured as described.
