# OI01-12 Dependency and duplication audit

Date 2026-11-24. Tool: `tools/deps.py` (standard library). Report: [docs/quality/deps.md](../../quality/deps.md).
Baseline: `docs/quality/deps_baseline.json`.

## What the map shows (measured on this HEAD)

- 201 addon files. Each `ns.Name =` assignment marks the owner of a public handle.
- 32 mutual file pairs (A uses B and B uses A), forming 5 strongly connected groups. The largest has
  41 files: the class, fight, macro, profession, fishing and map modules that call each other at
  runtime. Calls between modules are normal in this addon, so these are the accepted baseline.
- 48 reads of another module's lowercase (state) fields, for example `ns.Inventory.db`,
  `ns.Layers.current`, `ns.Snapshot.asking`. `.enabled` is the lifecycle flag and counts as public.
  These are the "private coupling" baseline.
- 3 internal events are fired with no listener: `OTR_LAYER_CHANGED`, `OTR_PROFILE_CHANGED`,
  `OTR_TRAINER_READ`. They are kept as hooks; nothing was removed.
- Duplicated helpers: `readable(v)` appears in 22 files in two variants, and `known(name)` in 5. They
  are candidates for one shared Compat helper, listed rather than changed (an adapter refactor is a
  separate step).

## Gate

`tools/test.ps1` (local and CI) now runs `deps.py --check`. A new mutual pair or a new private field
read fails the suite until it is reviewed and added to the baseline. The new private reads added
today (Prices to PriceHistory, FishBook to FishingGuide) are in the baseline and named in the report.

## Dead code

No code was removed. The blueprint allows removing only verified unreachable code, and nothing
found so far is verified unreachable (the unlistened events are part of a public pattern).
Fixture outputs are unchanged: the full suite gives 1016 passed, 0 failed.
