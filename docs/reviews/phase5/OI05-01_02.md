# OI05-01 Scenario contract and OI05-02 Oracle comparisons

## OI05-01: `Intelligence/Scenario.lua`

**Acceptance:** before/after actual state hash unchanged; an invalid hypothetical item, role or level is rejected; assumptions and version included.

**`Base()`** copies the live character: level, class, role, gold, worn gear by slot, talent points per tree, professions and zone.

**`Branch(base, overrides, assumptions)`** returns a new **frozen** scenario; writing to it raises "branch a new one". The overrides are:
- gear by slot
- talent points per tree (total no more than level − 9)
- spend (no more than the gold you have)
- a role your class can play
- zone
- professions (0 to 450)
- level (1 to 60)

Invalid overrides are refused with the reason, never adjusted. Each scenario carries its version, a base hash, the overrides and the assumptions.

**No mutation:** it never writes saved data or changes the game. Tests show the live character's hash and the base copy's hash are both unchanged after branching.

## OI05-02: `Intelligence/Oracle.lua`

**Acceptance:** no fabricated precise gain; missing data compares only known dimensions; a stale base requires a refresh; works offline.

**Known dimensions:**
- gold: exact
- changed gear slots: GearScore's role score versus what you wear, rounded to whole percent; an empty slot counts as 0
- level, role and professions: plain differences
- talent points: shown as distributions
- zone risk: Guardian
- plan value: the planner re-run for each scenario's gold and place over the current opportunities, labelled "relative planner score, not a promise"

**Unknown dimensions** are listed, never filled in: an item the scorer can't read, the effect of a talent change (the Forge, later), and the plan when there's no current plan.

**Stale:** scenarios from different snapshots, or a live character changed since, return "refresh". Everything is offline.
