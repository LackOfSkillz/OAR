## VG07-02: Privacy-filtered import/export

- **Contract:** RunRecord v1 fields only. The Lua spec drives `Runs.Enter/EncounterStart/End/Close` and checks every field it writes against the shared fixture, including the assessment fields the module copies.
- **Export** (`contract.build_export`):
  - Includes active runs and archived runs for one character, deduplicated by run id, with the latest revision kept.
  - Fields outside the contract are dropped and counted.
  - A run containing a GUID-shaped value or a character name from the file is refused.
  - The exporter is the opaque id `c` + adler32(salt|Name-Realm); with no salt, the export is refused.
  - The profile (class and level only) is included only with `--profile`. Guild use needs `--guild`.
  - Preview is the default. A file is written only with `--out`, only with the game closed, and never inside WTF or Interface.
- **Import** (`contract.read_import`): strict. Any of these refuses the whole file:
  - wrong format or bad JSON;
  - a newer version (the message says to update);
  - any unknown field;
  - an exporter that isn't an opaque id;
  - consent missing one of its three answers;
  - a profile without consent, or with fields other than class and level;
  - a bad type, or a size over the caps (5 MB, 5000 runs, 60 attempts).
- **No live bridge:** files only, moved by the player. No network: the integration test blocks sockets and every command still works.
- **Tests:** `ContractTest` (the 5 shared fixture cases, anonymity, preview, game-open refusal, game-folder refusal, missing salt, 10 strict-import refusals) and the Lua contract test.

## VG07-03: Vault

- **Location:** `%LOCALAPPDATA%\Outrider\CommandCenter\vanguard.sqlite`, configurable, and refused inside the game folder.
- **Storage:** STRICT tables. Canonical JSON with sha256. Each import is one transaction, and every row gets a provenance row.
- **Idempotent:** the same file again is "skipped" with nothing changed. A changed run becomes revision n+1, and the old revision is kept.
- **Scoped queries:** one exporter at a time, unless "everyone" is asked for explicitly. Asking without a scope is refused.
- **Failures and damage:**
  - A failed import is rolled back and recorded as failed.
  - A damaged file opens read-only and refuses imports.
  - A newer schema opens read-only.
- **Backup:** the sqlite backup API, and an existing backup is never overwritten.
- **Restore:** checks the backup first. The replaced file is kept beside it, never deleted.
- **Tests:** `VaultTest`, 4 tests.

## VG07-04: Scenario analysis

- **Input:** a hypothetical group of 1 to 40 members (class, role, level). An impossible role for the class is refused.
- **Output:**
  - Role counts.
  - What the group can bring: from the addon's class lists, shown as "potential, if trained".
  - Each boss's needs, covered or missing, plus "watch" notes. All from the researched facts, labeled "from a guide", `verified = false`, and Classic-based where it applies.
  - Raid size and status notes.
  - Similar past runs from your vault, described with a Wilson interval. Under 5 known runs, it abstains.
- **Limits** are printed with every answer, ending "Nothing here is a success probability."
- **No gameplay controls:** the output is text or JSON only.
- **Tests:** `ScenarioTest`, 4 tests.

## VG07-05: Forecast offline pipeline

- **Follows** `VG05-07_FORECAST_PLAN.md`:
  - The three targets, kept separate.
  - Unknown attempts and censored runs are excluded and counted.
  - Aggregate features only.
  - Cohort = target and place.
  - Floors: 200 training runs, 50 held out, 10 of each outcome.
  - Abstains when one outcome is above 95% or when game builds or catalog versions are mixed.
  - Chronological split, grouped by run.
- **Models:** prevalence baseline, a role-and-level logistic model, and a regularized logistic model. All deterministic and in pure Python.
- **Metrics:**
  - Brier score, with a bootstrap interval against the baseline.
  - Reliability bins with counts.
  - Calibration slope and intercept, with an interval on the slope.
  - AUC, reported but not used to pass.
  - Dataset, training and holdout sha256.
- **Pass rule (our reading, for the reviewer to confirm):** the upper end of the 95% interval of (model Brier − baseline Brier) must be ≤ 0.
- **Plan approval:** without `vanguardForecast.planApprovedBy` in `companion/policy.json`, nothing is fitted. It isn't approved in this repository.
- **Never approved by code:** `approved` is always false. Synthetic records are left out, and a card built with them is never eligible.
- **Not shipped:** nothing is written into the addon. `Forecast.lua` in game still abstains.
- **Tests:** `ForecastTest`, 5 tests. Synthetic data is used only to exercise the math, and those cards are never eligible.

## VG07-06: Guild preparation and reports
